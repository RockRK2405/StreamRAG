# 03: BM25 Lexical Retrieval

**Code:** `retrieval/text.py` (analyzer), `retrieval/bm25.py`, `retrieval/topk.py`
**ADR:** ADR-001

## Purpose

Exact-term matching: entities, numbers, policy names. This is the sparse half of hybrid retrieval.

## Architecture

**Analyzer.** The same analyzer runs at index and query time:

1. Lowercase and NFKC.
2. Tokens = letters or numbers (`1,000` → `1000`).
3. Spoken number words become digits (`thirty five` → `35`).
4. Remove generic English stopwords (`resources/stopwords_en.txt`). Negations are kept, and spoken fillers are dropped.
5. Snowball English stemming.

**Index.** Precomputed BM25 weights in a scipy CSC matrix (chunks × terms, float32):

`w(t,d) = idf(t) · tf·(k1+1) / (tf + k1·(1 − b + b·|d|/avgdl))`, with `idf = ln(1 + (N − df + .5)/(df + .5))`.

**Search.** Sum the matrix columns of the unique query terms. Only positive scores qualify. Results are ordered by `deterministic_topk`: score descending, ties by row.

## API

| Call | Behavior |
|---|---|
| `BM25Index.build(texts, analyzer, k1, b)` | Build the index |
| `.search(query, analyzer, top_k, mask=None)` | Returns `[(row, score)]` |
| `.save(dir)` / `BM25Index.load(dir)` | Persist to `weights.npz`, `doc_len.npy`, `vocab.json`, `meta.json` |
| `.query_terms(query, analyzer)` | Diagnostics |

Through the service, each `Evidence` carries `bm25_score`, `bm25_rank` and `retrieval_method = "bm25"` (or `hybrid_*`).

## Configuration

`lexical.k1` (1.5), `lexical.b` (0.75), `lexical.stemming` (`snowball|none`), `lexical.stopwords`, `lexical.normalize_number_words`, `retrieval.lexical_k` (50).

## Behavior (tested)

| Case | Result |
|---|---|
| Exact keyword | Ranks first |
| Partial matches | Rank (BM25 is additive over terms) |
| Terminology variation | Handled by stemming (`trimming` ~ `trimmed`, `lenses` ~ `lens`) |
| Number words | Matched on both sides |
| Empty or stopword-only query | `[]` at the index level; the service raises `InvalidQueryError` for empty queries |
| No vocabulary overlap | `[]`, plus warning `no_lexical_terms_in_vocabulary` |

## Performance (measured, synthetic)

| Metric | 2k chunks | 10k chunks |
|---|---|---|
| Query p50 | 0.10 ms | 0.17 ms |
| Build | 1.3 s | 6.7 s |
| Matrix size | — | 3.1 MB |

## Failure modes

- A corrupt or inconsistent artifact raises `IndexCorruptError` (shape and vocabulary check, plus the manifest checksum).

## Trade-offs

- No synonyms. "refund" does not match "reimbursement"; that is the dense retriever's job.
- Stemming can conflate rare word pairs.
- Python-side tokenization makes index builds O(seconds) at 10k chunks. That is acceptable at build time.
